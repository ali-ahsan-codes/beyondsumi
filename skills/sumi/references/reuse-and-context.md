# Reuse before regeneration; read only relevant detail

Read the current project summary and changed brief first. Use the latest approved script, direction, assets, raw takes, sound bank and event ledger. Look up compatible existing assets/settings/hashes before another generation. Check view, identity, action, resolution, contact and style compatibility; filename similarity alone does not justify reuse.

For each new image/voice/effect request record its final inputs, model/settings, reference hashes, scope and returned job/receipt. A completed matching request is reused; an uncertain request is checked through its history before any retry. Do not make a second setup sample when the requested triptych/proof already tests that route. Do not rebuild another edition unless requested.

Keep one canonical copy of shared rules and link it. Load setup only on first use or a relevant capability change, one chosen style, one chosen provider, and action/environment detail required by the current shot. Do not recursively read every linked reference or copy full manuals into chat/project memory. Legacy mechanisms are conditional research, not startup reading. The standalone provider companion and project-export adapter may carry the same implementation for portability; choose one execution path, not both.

Reuse frame-clock helpers and existing dependencies. Project initializers reference the shared music bank instead of copying it into every film. Keep selected cache files outside the public package and copy only what a self-contained deliverable actually needs. Do not convert a tested local dependency into a new download just to follow a template.

On a revision update the affected shots/cues and their dependent checks, preserving valid evidence for unchanged sources. Run appropriate checks once; broaden/repeat only after new changes, failures or unresolved concerns. Keep concise current memory with links to historical records; archive recoverable history instead of repeatedly loading it. Report measured bytes/read size/asset calls when available; do not equate filesystem savings or frame rate with measured model-token savings.
